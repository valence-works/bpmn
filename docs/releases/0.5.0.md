# BPMN 0.5.0 migration and release notes

Changes relative to v0.4.0. Verify the [release and artifact qualification record](https://github.com/valence-works/bpmn/issues/95)
before upgrading; a build from main or a Feedz preview does not establish stable package availability.
All four packages move together: `Bpmn.Model`, `Bpmn.Interchange`, `Bpmn.Semantics`, and
`Bpmn.Runtime.InMemory`, targeting `net8.0` and `net10.0` with no shipped external NuGet dependencies.

## Upgrade the payload reader and host together

The package version is **0.5.0**; the separately versioned payload format moves from **1.5.0** in
v0.4.0 to **1.10.0**. Upgrade consumers of the closed JSON Schema before sending newly written
payloads. New readers accept older payloads with the optional fields absent. Downgrade compatibility
is not implied: older polymorphic readers reject newly introduced binding kinds.

| Format | Change since the v0.4.0 payload |
| --- | --- |
| 1.6.0 | Optional element `script`, carrying script body and format. |
| 1.7.0 | `signalPublish` work-binding case. |
| 1.8.0 | `timerDateWait` work-binding case. |
| 1.9.0 | `timerCycleWait` work-binding case, retaining cycle text, start and repetition information. |
| 1.10.0 | Optional `valueNamespaces` on retained attributes, with `BpmnNamespaceBinding` provenance. |

The schema still has the same three roots: definitions, execution state and work binding. It ships
inside `Bpmn.Model` at `schema/bpmn-payload.schema.json`. Host values and commands have separate JSON
contracts; the changes below are not extra payload roots. See [the format contract](../reference/packages.md#the-serialization-is-owned-and-versioned).

Before adopting, retain a tested backup of definitions, execution state and the host's work ledger.
Qualify persistence, callbacks, cancellation, recovery and authoring in the actual host; the reference
host and library conformance suite do not establish durable or distributed execution.

## Host compatibility changes

### Keep work identities in the ledger

Save each `StartWork.TokenId` with its host handle, return it as `WorkTokenId` in live-work snapshots,
and echo it in completion, fault and signal callbacks. This additive init property leaves the existing
positional constructors and deconstruction signatures intact. It distinguishes concurrent ordinary
invocations sharing a binding and null iteration; an ID-less callback requires an unambiguous exact
binding/iteration slot. Explicit IDs are checked strictly and must agree with the matching snapshot.
Remove terminal work from `LiveWork` before reporting its completion or fault; recognized active
signals still need their matching live handle.

Never reuse a handle within a scope's lifetime. ID-less late callbacks retain legacy handle-based
stopped-work absorption; token-ID checks do not turn handle reuse into a supported host practice.
See [the callback contract](../concepts/host-port.md#callbacks-for-work-already-stopped) and
[ADR 0010](../adr/0010-work-callbacks-echo-the-started-token.md).

### Treat producer provenance as reporting data

`StartWork.ProducedByHandle` is a nullable init property, outside the seven positional values.
Ordinary routing reports the completed/faulted producer handle, or the scope identity for scope-driven
propagation. Scope-owned starts, including listeners, multi-instance instances, compensation and
event-subprocess bodies, leave it null. It is not a callback or ownership key and does not assert
producer success.

New command JSON adds `ProducedByHandle`; older JSON without it reads as null. Update closed command
schemas. The property participates in record equality: commands with different producers compare
unequal. Review command comparison, keying and deduplication code. See
[the provenance amendment](../adr/0002-the-host-port-is-synchronous-and-command-returning.md#2026-10-17-amendment-scheduling-provenance).

### Preserve refused values and omit the derived boolean

`BpmnValuePresence.Refused` appends ordinal 4; previous ordinals 0–3 keep their values. The
`BpmnValue.Refused(code, message)` factory and optional `faultCode` / `faultMessage` distinguish a
withheld value from absent, null or external storage. Collection-mode multi-instance evaluation
returns the host's fault code/message without starting iterations. Exhaustive presence consumers
must handle the new case.

New host-value JSON **omits `HasValue`**. Its C# computed getter, constructor and three-value
deconstruction remain. Legacy JSON containing `HasValue`, or `hasValue` under camel-case options,
still reads, including strict unmapped-member handling; the supplied boolean does not override the
computed result. Update any host schema or consumer requiring this derived field. See
[the host-value migration](../adr/0002-the-host-port-is-synchronous-and-command-returning.md#2026-10-25-amendment-computed-host-values).

### Apply signals on a fault and capture history before pruning

A signal raised before a later ordinary fault must still reach the enclosing scope. Apply returned
`SignalEnclosingScope` commands in order before forwarding the fault, or commit them atomically with
it. The reference host now preserves this path. The interpreter deliberately withdraws signals when
its evaluation hits the propagation limit; deferred legacy pending-fault paths have separate handling.
See [ADR 0009](../adr/0009-raised-escalations-survive-a-later-fault.md).

`Prune()` now removes canceled tokens once no active work references them and no unresolved
stopped-work handle remains. Capture cancellation transitions from each evaluation's **unpruned**
state if the host needs history. The reference transcript uses `BpmnTranscriptEntry.TokenMoves`;
a UI must not rely on canceled tokens remaining in persisted `State.Tokens`.

A stopped handle remains until its late terminal callback is absorbed. If the callback never arrives,
state can still grow without a fixed count or time limit; this release adds no forget API or expiry.
See [the state contract](../concepts/host-port.md#the-prior-state).

## Interchange and composition changes

- Host availability assessment is optional and happens after import, with the host's own inventory:
  `BpmnWorkAvailabilityValidator.Assess`. It preserves all ordered results and the imported model.
  `Unknown` is not ready; `AllWorkAvailable` is true only when all results are available. Availability
  does not prove graph validity or host capabilities. Existing default `UnboundTask` import remains.
- Escalation boundaries now accept Call Activities as well as Sub-Processes. Ordinary task hosts are
  still rejected. Qualify both interrupting teardown and non-interrupting continuation in the host.
  Host-provided ordinary Task compensation handlers are accepted; Call Activity compensation behavior
  is unchanged. Call Activity BPMN error-code forwarding was already required in v0.4.0 and remains so.
  See [ADR 0013](../adr/0013-host-work-availability-is-assessed-after-import.md).
- Structured refusal `ElementIds` support model placement without parsing messages, including all nine
  element-specific family-resolution refusals. Rejection predicates and messages are preserved for
  that correction; exceptions without a specific element can still have no IDs.

### Retained QName values now carry namespace context

Recognized prefixed QName attribute values and XML-whitespace-separated QName lists retain bound and
observed-unbound prefixes through XML → model JSON → XML, including inherited/local shadowing.
This uses optional, non-positional `BpmnForeignAttribute.ValueNamespaces`; existing two-argument
construction/deconstruction remain, and provenance compares structurally.

Recognition is lexical, independent of vendor typing: `urn:value` also matches. Arbitrary expressions,
unprefixed QName values and QName element text are outside this rule. Legacy JSON without provenance
still reads but cannot reconstruct namespace context already discarded; re-import the original XML
for that. Namespace context is not necessarily a vendor dependency or a separate import diagnostic.

Export raises `BpmnInterchangeException` for incompatible mappings or a collision with required fixed
prefixes instead of silently changing resolution. Existing BPMN `xsi:type` normalization can itself
conflict with another retained value that uses a locally rebound `bpmn` prefix; this unusual valid
source is refused explicitly. Review such a refusal rather than treating export as infallible.
When a retained QName value locally shadows a prefix used by the element or one of its attribute
names, export now assigns a safe local alias to that XML name. The emitted document preserves both
the expanded name and the retained value's binding, including after model JSON round-trip.
A caller changing a retained attribute's value must update or clear its provenance.
See [the fidelity contract and limitations](../adr/0006-vendor-extensions-are-retained-as-typed-data.md#2026-10-25-amendment-namespace-provenance-in-attribute-values).

## Qualifying exact package artifacts

Run [the package verifier](../../tools/release/verify_packages.py) against an external directory
containing all four `.nupkg` and `.snupkg` artifacts. Supply the exact package version and source
commit recorded in their metadata; `python3 tools/release/verify_packages.py --help` lists the options.
It checks the package graph, framework assemblies, symbols and payload schema, then restores an
independent consumer into an isolated cache. BPMN packages resolve only from that local feed;
Microsoft SDK reference/apphost packs can resolve from NuGet.org through a restricted source mapping.
It records separate compile and
execution results for .NET 8 and .NET 10 outside the source tree. A missing SDK/runtime or a skipped
execution does not count as a pass. This library-level check complements actual host qualification.

## Recovering from an upgrade problem

Stop the rollout and retain the exact package versions, source SHA, payload format, input document,
prior state, host snapshot and event. Reproduce against those inputs before changing data. Publishing
four packages is not an atomic rollback mechanism: published versions cannot be overwritten, and a
partial publish must be completed or repaired with a new version.

Do not blindly downgrade after persisting new binding kinds or namespace metadata. Pin all four
packages to a previously qualified version only with data it can read; otherwise use a tested backup
or an explicit migration/fix-forward plan. A source revert does not undo persisted payload changes or
external work already performed.
